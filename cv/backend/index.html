Summary

Backend and platform engineer with ~6 years building the services, API clients, and release infrastructure behind an autonomous vehicle fleet’s connectivity platform. Designed and shipped a scoring service in C++ behind a REST endpoint with fail-safe error semantics; replaced per-request device round trips with a server-side cache, then fixed its read-after-write consistency with push-based invalidation; wrote the client library that drives a third-party carrier provisioning platform; and built the signed artifact pipeline that has delivered every firmware release to production for the past three years. Strongest on distributed-systems problems: reconciling declared state against observed state, cache coherency, idempotent retry and rollback semantics, and failure handling that degrades instead of cascading.

Distributed systems & reliability — declared-versus-observed state reconciliation, cache coherency and invalidation, read-after-write consistency, idempotency and bounded retry, rollback and graceful degradation, push-based event propagation, fault isolation, single-point-of-failure analysis and mitigation planning.

Languages — Python (service clients, CLIs, build systems, and test frameworks; multi-thousand-line packages as sole author), C++ (production services, gTest), Bash.

Experience

Service implementation and API design

  • Designed and implemented a C++ scoring service end to end (algorithm, config loader, telemetry cache, gTest) served over REST with fail-safe semantics: internal errors return a zero score rather than an HTTP failure. Consumed by the production call-routing path.
  • Replaced per-request device round trips with server-side aggregation and caching, then fixed read-after-write staleness with push invalidation driven by the device’s property-changed event.
  • Owned the REST surface the fleet orchestration layer calls — including a live GET-to-POST migration, soft-maintenance mode, and profile-recommendation / deploy-matrix endpoints — plus a CI contract-validation framework for the whole surface.

Third-party API integration

  • Wrote a ~1,900-line carrier-platform API client/CLI (sole author) with a checked HTTP client, orchestration layer, and provider-profile hierarchy that hides operator differences behind one interface; delivered as a five-PR stack with a full unit suite.
  • Solved upstream read-after-write inconsistency with a per-resource dirty flag that forces refresh on the next read, eliminating a class of false failures; wrote a second OpenAPI client when the platform moved to a different provisioning standard.

Distributed state and orchestration

  • Own multi-operator configuration management as versioned, reviewed profile sets selected by a deploy matrix so only reviewed parameters reach production.

Build, release, and artifact infrastructure
